# Як долучитися

Дякуємо, що хочете допомогти `keycrm-mcp-go`! Цей документ пояснює, як підготувати зміну і чому перед першим pull request треба підписати CLA.

## Перед початком

- Для великої зміни (новий toolset, зміна поведінки інструментів запису, нова залежність) спершу відкрийте issue й обговоріть підхід.
- Сервер працює **лише з офіційним публічним API** keyCRM (`https://openapi.keycrm.app/v1`). Кожен інструмент відповідає `operationId` з `pkg/keycrm/api.yaml`; внутрішні ендпоїнти веб-інтерфейсу keyCRM не використовуємо.
- Знайшли вразливість? Не відкривайте issue — див. [SECURITY.md](SECURITY.md).

## Розробка

Потрібні Go (версія з `go.mod`) і [golangci-lint](https://golangci-lint.run/) v2.

```bash
make build      # бінарник bin/keycrm-mcp
make test       # go test -race ./...
make check      # gofmt + golangci-lint + go vet + тести
make generate   # go generate ./...
make security   # govulncheck + gitleaks
```

Правила коду:

- `gofmt`/`goimports` обов'язкові; кожен `.go` файл починається з `// SPDX-License-Identifier: AGPL-3.0-only`.
- Помилки обгортаємо через `fmt.Errorf("…: %w", err)` і порівнюємо через `errors.Is/As`; жодна помилка не ігнорується.
- Тести табличні, з `t.Run`; замість моків — фейки (`httptest.Server`, що емулює keyCRM). Автоматичні тести **ніколи** не виконують запис у справжній keyCRM.
- У логи не потрапляють телефони, email, імена, адреси, нотатки, ключі й токени.
- Коментарі в коді, описи інструментів, повідомлення комітів і опис PR — українською. Ідентифікатори й назви MCP-інструментів — англійською.
- Коміти — у стилі [Conventional Commits](https://www.conventionalcommits.org/uk/v1.0.0/): `feat:`, `fix:`, `docs:`, `chore:`, `build:`; повідомлення пояснює, *навіщо* зміна.

## Pull request

1. Зробіть fork і гілку від `main` (`feature-<slug>`, `fix-<slug>`).
2. Переконайтеся, що `make check` проходить.
3. Відкрийте pull request: що змінено і навіщо.
4. Підпишіть CLA, коли бот попросить (один раз).

## Угода про внесок (CLA)

### Навіщо CLA, якщо проєкт під AGPL

Код поширюється під [AGPL-3.0](LICENSE): кожен може користуватися ним, змінювати й поширювати на умовах AGPL. CLA цього не змінює. Угода потрібна, щоб власник проєкту міг:

- **ліцензувати проєкт на інших умовах** — наприклад, надати комерційну ліцензію компанії, яка не може прийняти умови AGPL, і так фінансувати розвиток;
- **змінити ліцензію в майбутньому**, не шукаючи згоди кожного автора окремо;
- **захищати проєкт** — мати чітке підтвердження, що кожен автор мав право надіслати свій код, з патентною ліцензією на нього.

Ви **зберігаєте авторське право** на свій внесок; CLA лише надає власнику проєкту безвідкличну ліцензію з правом субліцензування. Повний текст — [docs/CLA.md](docs/CLA.md).

### Як працює CLA Assistant

1. Ви відкриваєте pull request.
2. Бот [CLA Assistant](https://cla-assistant.io/) перевіряє, чи всі автори комітів підписали угоду. Якщо ні — він залишає коментар із посиланням, а перевірка `license/cla` стає червоною.
3. Ви переходите за посиланням, входите через GitHub і підписуєте угоду **одним кліком**.
4. Перевірка стає зеленою. Підпис діє для всіх подальших PR, доки текст угоди не зміниться.

Кожен автор коміту в PR має бути прив'язаний до облікового запису GitHub (email коміту має збігатися з одним із email вашого акаунта).

### Для власника: підключення CLA Assistant

Робиться один раз вручну:

1. Створіть **публічний** gist на <https://gist.github.com/> з одним файлом, напр. `keycrm-mcp-go-cla.md`, і вставте в нього повний текст [docs/CLA.md](docs/CLA.md).
2. Відкрийте <https://cla-assistant.io/> і увійдіть через GitHub (**Sign in with GitHub**), надавши доступ до репозиторіїв.
3. Натисніть **Configure CLA**: у полі репозиторію виберіть `grengojbo/keycrm-mcp-go`, у полі CLA — створений gist. Натисніть **Link**.
4. Перевірте на тестовому PR, що бот залишає коментар і з'являється перевірка `license/cla`.
5. За бажанням — у **Settings → Branches** додайте `license/cla` до обов'язкових перевірок для `main`.

Коли текст `docs/CLA.md` змінюється, оновіть gist: CLA Assistant попросить учасників підписати нову версію.
